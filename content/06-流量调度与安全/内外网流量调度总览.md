# 内外网流量调度总览

## 先分清流量方向

| 方向 | 含义 | 例子 |
|---|---|---|
| 南北向 | 内部网络与外部网络之间 | 员工上网、用户访问网站 |
| 东西向 | 同一数据中心/云/内网内部 | Web 访问 App，App 访问 DB |
| 入站 Ingress | 外部进入内部服务 | 公网用户访问企业 Web |
| 出站 Egress | 内部主动访问外部 | 服务器下载补丁、员工访问 SaaS |

## 调度发生在哪里

```mermaid
flowchart LR
  User[用户/客户端] --> DNS[DNS/GSLB]
  DNS --> CDN[CDN/Anycast/边缘节点]
  CDN --> LB[负载均衡]
  LB --> FW[防火墙/WAF]
  FW --> App[应用集群]
  App --> DB[数据库/后端]
```

调度可能发生在多层：

- DNS 层：返回不同 IP。
- BGP 层：Anycast 把用户引到最近入口。
- L4 层：按五元组分发 TCP/UDP。
- L7 层：按域名、路径、Header、Cookie 分发。
- 应用层：灰度、熔断、服务发现。
- 路由层：ECMP、策略路由、SD-WAN。

## 出站流量调度

内部访问公网时，常见路径：

```text
终端/服务器 -> 网关 -> 防火墙 -> NAT/代理 -> 运营商 -> 互联网
```

可能的策略：

- 普通上网走代理或安全网关。
- 关键 SaaS 走专线或 SD-WAN 优选链路。
- 服务器出网走 NAT Gateway。
- 数据库禁止直连公网。
- 高风险目的地址被防火墙阻断。

## 入站流量调度

公网访问内部服务时，常见路径：

```text
用户 -> DNS/CDN -> 公网负载均衡/WAF -> 防火墙 -> 反向代理/服务网关 -> 应用
```

可能的策略：

- GSLB 按地理、运营商、健康状态返回入口。
- CDN 缓存静态内容。
- WAF 拦截常见 Web 攻击。
- L7 负载均衡按域名和路径转发。
- 内部服务只接受来自负载均衡的流量。

## 云上调度

云上常见组合：

- 公网 DNS -> CDN -> Global Load Balancer -> 区域负载均衡。
- 私有子网 -> NAT Gateway -> Internet Gateway。
- Spoke VPC/VNet -> Hub 防火墙 -> 专线/VPN/互联网。
- Pod -> Service -> Ingress/Gateway -> Load Balancer。

## 关键风险

- 回程路径不一致导致有状态防火墙丢包。
- DNS 缓存导致切流不及时。
- NAT 端口耗尽。
- 负载均衡健康检查与真实业务状态不一致。
- 安全策略只看入口，忽略东西向横向移动。
