# 地址规划与 IPAM

## 为什么地址规划重要

地址规划一旦混乱，后续 VPN、专线、云互联、容器网络、多云都会变难。最严重的问题是网段重叠，路由器无法判断同一个目的地址到底在哪。

## 规划原则

- 按组织、区域、环境、业务分层。
- 给未来扩容预留空间。
- 本地、云、容器、VPN 对端避免重叠。
- 管理网、生产网、办公网、访客网分开。
- 文档化每个网段用途和负责人。

## 示例

```text
10.0.0.0/8        企业总私网池
10.10.0.0/16      总部园区
10.20.0.0/16      数据中心
10.30.0.0/16      AWS
10.40.0.0/16      Azure
10.50.0.0/16      GCP
10.60.0.0/16      Kubernetes Pod/Service
```

## IPAM

IPAM 是 IP 地址管理。它记录：

- 网段分配。
- IP 使用情况。
- DNS 名称。
- VLAN/VRF。
- 所属业务。
- 生命周期。

## 容器和云的特殊问题

- Kubernetes Pod CIDR 和 Service CIDR 也要纳入规划。
- 云 VPC 创建后 CIDR 调整可能受限制。
- 多云私网互联时，重叠地址经常导致 NAT 复杂化。
- SaaS/合作伙伴 VPN 也可能带来冲突网段。
